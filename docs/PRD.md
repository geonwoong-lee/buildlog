# BuildLog 제품 요구사항 문서(PRD)

## 1. 문서의 목적

이 문서는 BuildLog의 첫 번째 버전을 만들기 위한 제작 주문서입니다.

무엇을 왜 만드는지, 사용자에게 어떤 기능과 화면이 필요한지, 어디까지 만들어야 완성인지 설명합니다. 기능 범위는 `mvp.md`에서 정한 내용을 기준으로 하며, 정하지 않은 내용은 임의로 결정하지 않고 `미정`으로 표시합니다.

## 2. 서비스 한눈에 보기

BuildLog는 공부와 프로젝트를 진행하면서 생기는 기록을 한곳에 모아두는 개인용 웹사이트입니다.

사용자는 다음 세 종류의 정보를 관리할 수 있습니다.

- 오늘 공부한 내용
- 앞으로 공부하거나 프로젝트에서 해야 할 일
- 개발 중 만난 오류와 해결 방법

웹사이트에 저장된 내용은 여러 컴퓨터에서 같은 계정으로 확인할 수 있어야 합니다. PC와 휴대폰에서도 주요 기능을 편하게 사용할 수 있어야 합니다.

## 3. 누가 사용하는 서비스인가요?

첫 번째 사용자는 BuildLog를 만든 본인 한 명입니다.

이 사용자는 다음과 같은 사람입니다.

- 공부와 프로젝트 기록을 꾸준히 남기고 싶습니다.
- 메모장과 AI 대화 등 여러 곳에 흩어진 기록을 한곳에 모으고 싶습니다.
- 다른 컴퓨터에서도 같은 기록을 보고 싶습니다.
- 복잡한 설정 없이 기록하고 검색하고 싶습니다.

첫 버전은 개인용입니다. 다른 사람이 직접 회원가입하거나 여러 계정을 관리하는 기능은 만들지 않습니다.

## 4. 어떤 불편을 해결하려고 하나요?

### 기록이 여러 곳에 흩어지는 문제

공부한 내용을 메모장, AI 대화 등 서로 다른 곳에 적으면 나중에 어디에 기록했는지 기억하기 어렵습니다. BuildLog는 학습 기록을 한곳에 저장하고 다시 볼 수 있게 합니다.

### 해야 할 일을 놓치는 문제

앞으로 공부할 내용과 프로젝트 할 일을 따로 관리하지 않으면 무엇이 끝났고 무엇이 남았는지 확인하기 어렵습니다. BuildLog는 할 일을 적고 완료 여부를 체크할 수 있게 합니다.

### 같은 오류를 다시 조사하는 문제

오류가 발생했을 때 원인과 해결 방법을 남기지 않으면 비슷한 오류를 만났을 때 처음부터 다시 찾아봐야 합니다. BuildLog는 해결 전 오류도 먼저 저장하고, 해결한 뒤 해결 방법을 덧붙일 수 있게 합니다.

## 5. 제품 목표

첫 번째 버전의 목표는 다음과 같습니다.

1. 공부한 내용을 제목과 본문으로 저장하고 다시 볼 수 있습니다.
2. 해야 할 일을 저장하고 완료한 일과 남은 일을 구분할 수 있습니다.
3. 오류와 해결 과정을 저장하고 나중에 검색할 수 있습니다.
4. 본인만 로그인하여 기록을 볼 수 있습니다.
5. 여러 컴퓨터에서 같은 데이터를 확인할 수 있습니다.

## 6. 기능 요구사항

### 6.1 로그인

사용자는 본인 계정으로 로그인할 수 있어야 합니다.

- 로그인하지 않은 사람은 기록을 볼 수 없어야 합니다.
- 첫 버전에는 회원가입 기능을 넣지 않습니다.
- 여러 사용자 계정을 관리하는 기능을 넣지 않습니다.
- 비밀번호 같은 중요한 정보는 코드나 공개 저장소에 직접 적지 않습니다.

로그인 방식과 본인 계정을 처음 만드는 방법은 아직 정하지 않았습니다.

### 6.2 학습 기록

사용자는 공부한 내용을 기록하고 관리할 수 있어야 합니다.

- 새 학습 기록을 작성하고 저장할 수 있습니다.
- 저장한 학습 기록을 목록으로 볼 수 있습니다.
- 목록에서 하나를 선택해 자세히 볼 수 있습니다.
- 기존 기록을 수정할 수 있습니다.
- 필요 없는 기록을 삭제할 수 있습니다.
- 제목과 내용으로 기록을 검색할 수 있습니다.

학습 기록에 저장할 정보는 다음과 같습니다.

| 항목 | 설명 |
| --- | --- |
| 제목 | 무엇을 공부했는지 알아볼 수 있는 제목 |
| 공부한 내용 | 사용자가 작성한 학습 내용 |
| 작성일 | 기록을 처음 작성한 날짜와 시간 |
| 마지막 수정일 | 기록을 마지막으로 수정한 날짜와 시간 |

### 6.3 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 일을 관리할 수 있어야 합니다.

- 새로운 할 일을 추가할 수 있습니다.
- 일을 끝내면 완료 여부를 체크할 수 있습니다.
- 완료하지 않은 일을 먼저 볼 수 있습니다.
- 완료한 일은 완료 목록에서 확인할 수 있습니다.
- 완료 여부를 변경할 수 있습니다.

할 일에 저장할 정보는 다음과 같습니다.

| 항목 | 설명 |
| --- | --- |
| 할 일 내용 | 해야 할 공부나 작업의 내용 |
| 완료 여부 | 일이 끝났는지 나타내는 상태 |
| 작성일 | 할 일을 처음 작성한 날짜와 시간 |
| 완료일 | 할 일을 완료한 날짜와 시간 |

할 일의 예시는 `저장 버튼 만들기`, `파이썬 복습하기`입니다.

### 6.4 오류 기록

사용자는 공부나 개발 중 만난 오류와 해결 과정을 관리할 수 있어야 합니다.

- 해결하지 못한 오류도 먼저 저장할 수 있습니다.
- 저장한 오류 기록을 목록으로 볼 수 있습니다.
- 목록에서 하나를 선택해 자세히 볼 수 있습니다.
- 오류 기록을 수정할 수 있습니다.
- 필요 없는 오류 기록을 삭제할 수 있습니다.
- 나중에 해결 방법을 추가할 수 있습니다.
- 해결한 오류의 상태를 `해결 완료`로 바꿀 수 있습니다.
- 제목과 내용으로 오류 기록을 검색할 수 있습니다.

오류 기록에 저장할 정보는 다음과 같습니다.

| 항목 | 설명 |
| --- | --- |
| 오류 제목 | 어떤 오류인지 알아볼 수 있는 제목 |
| 오류 내용 또는 메시지 | 화면에 나온 메시지나 오류의 내용 |
| 오류가 생긴 상황 | 어떤 작업 중 오류가 발생했는지에 대한 설명 |
| 해결 여부 | 아직 해결 전인지, 해결 완료인지 나타내는 상태 |
| 해결 방법 | 오류를 어떻게 해결했는지에 대한 기록 |
| 작성일 | 오류를 처음 기록한 날짜와 시간 |
| 마지막 수정일 | 기록을 마지막으로 수정한 날짜와 시간 |

해결 방법은 처음 저장할 때 비어 있어도 됩니다.

### 6.5 검색

사용자는 예전에 작성한 기록을 제목이나 내용에 포함된 단어로 찾을 수 있어야 합니다.

기본 사용 순서는 다음과 같습니다.

1. 검색창에 찾고 싶은 단어를 입력합니다.
2. 제목이나 내용에 그 단어가 들어 있는 기록을 확인합니다.
3. 원하는 기록을 선택해 자세히 읽습니다.

검색창을 어디에 둘지, 모든 기록을 한 번에 검색할지 각 기록 화면에서 따로 검색할지는 아직 정하지 않았습니다.

### 6.6 여러 기기에서 사용

- 실제 서비스의 기록은 Supabase의 PostgreSQL 데이터베이스에 저장합니다.
- 로컬 개발과 자동 테스트에서는 SQLite 3를 사용합니다.
- 데이터베이스 종류가 달라도 입력 조건, 권한, 검색, 정렬 결과가 같아야 합니다.
- 다른 컴퓨터에서 로그인해도 같은 기록을 볼 수 있어야 합니다.
- PC와 휴대폰에서 주요 기능을 불편 없이 사용할 수 있어야 합니다.

## 7. 필요한 화면

### 7.1 로그인 화면

본인임을 확인하고 BuildLog에 들어가는 화면입니다. 로그인에 성공하면 홈 화면으로 이동합니다.

### 7.2 홈 화면

로그인 후 가장 먼저 보는 화면입니다.

- `학습 기록`, `할 일`, `오류 기록`으로 이동할 수 있습니다.
- 아직 완료하지 않은 할 일을 한눈에 확인할 수 있습니다.
- 아직 해결하지 못한 오류를 한눈에 확인할 수 있습니다.

홈에서 각 정보를 어떤 모양과 개수로 보여줄지는 아직 정하지 않았습니다.

### 7.3 학습 기록 화면

다음 작업을 할 수 있는 화면입니다.

- 학습 기록 작성과 저장
- 저장한 기록 목록 확인
- 기록 상세 내용 확인
- 기록 수정과 삭제
- 제목과 내용 검색

### 7.4 할 일 화면

다음 작업을 할 수 있는 화면입니다.

- 할 일 추가
- 완료 여부 체크
- 완료하지 않은 일 확인
- 완료한 일 확인

### 7.5 오류 기록 화면

다음 작업을 할 수 있는 화면입니다.

- 오류 기록 작성과 저장
- 저장한 오류 목록 확인
- 오류 상세 내용 확인
- 오류 기록 수정과 삭제
- 해결 방법 추가
- 해결 여부 변경
- 제목과 내용 검색

작성, 목록, 상세 보기, 수정 기능을 한 화면에 함께 둘지 여러 화면으로 나눌지는 아직 정하지 않았습니다.

## 8. 기본 사용 흐름

### 학습 기록을 남길 때

1. 로그인합니다.
2. `학습 기록`으로 이동합니다.
3. 제목과 내용을 작성합니다.
4. 저장합니다.
5. 목록에서 저장된 기록을 확인합니다.

### 할 일을 관리할 때

1. `할 일`로 이동합니다.
2. 새로운 할 일을 입력합니다.
3. 일을 끝낸 뒤 완료 체크를 합니다.
4. 완료한 일과 남은 일을 구분해서 확인합니다.

### 오류를 기록할 때

1. `오류 기록`으로 이동합니다.
2. 오류 제목, 내용, 발생 상황을 작성합니다.
3. 해결하지 못했더라도 먼저 저장합니다.
4. 해결한 뒤 기록을 다시 열어 해결 방법을 작성합니다.
5. 상태를 `해결 완료`로 바꿉니다.

### 예전 기록을 찾을 때

1. 검색창에 찾고 싶은 단어를 입력합니다.
2. 검색 결과를 확인합니다.
3. 원하는 기록을 선택해 다시 읽습니다.

## 9. 첫 버전 완료 기준

아래 항목이 모두 동작하면 BuildLog의 첫 번째 버전이 완성된 것으로 봅니다.

- 본인 계정으로 로그인할 수 있습니다.
- 로그인하지 않은 사람은 기록을 볼 수 없습니다.
- 학습 기록을 작성, 저장, 조회, 수정, 삭제할 수 있습니다.
- 할 일을 추가하고 완료 여부를 바꿀 수 있습니다.
- 완료한 일과 남은 일을 구분해서 볼 수 있습니다.
- 해결하지 못한 오류를 저장할 수 있습니다.
- 오류에 해결 방법을 나중에 추가할 수 있습니다.
- 오류 상태를 `해결 완료`로 바꿀 수 있습니다.
- 제목과 내용으로 필요한 기록을 검색할 수 있습니다.
- 다른 컴퓨터에서도 같은 데이터를 확인할 수 있습니다.
- PC와 휴대폰에서 주요 기능을 사용할 수 있습니다.

## 10. 이번에 만들지 않는 기능

다음 기능은 첫 번째 버전의 범위에 포함하지 않습니다.

- 누구나 가입할 수 있는 회원가입
- 여러 사용자의 계정 관리
- 다른 사람과 기록 공유하기
- 댓글과 좋아요
- 이미지와 파일 첨부
- 복잡한 통계와 그래프
- AI가 내용을 자동으로 요약하거나 분류하는 기능
- AI가 비슷한 오류를 추천하는 기능
- 알림과 일정 연동
- 태그와 카테고리
- 즐겨찾기
- 날짜별 학습 기록 모아보기
- 학습 시간과 완료한 일 통계
- 데이터 내보내기와 백업

여러 사용자 가입과 기록 공유는 나중에 필요성이 확인되면 다시 검토합니다.

## 11. 아직 정하지 않은 내용

아래 내용은 `mvp.md`에서 구체적으로 정하지 않았으므로 현재 상태는 `미정`입니다.

| 항목 | 현재 상태 |
| --- | --- |
| 로그인 방식 | 미정 |
| 본인 계정을 처음 만드는 방법 | 미정 |
| 화면의 색상, 글꼴, 구체적인 모양 | 미정 |
| 홈 화면에 보여줄 정보의 모양과 개수 | 미정 |
| 검색창의 위치 | 미정 |
| 전체 기록 통합 검색 여부 | 미정 |
| 각 입력 항목의 필수 입력 여부 | 미정 |
| 학습 기록과 오류 기록의 목록 정렬 기준 | 미정 |
| 작성·목록·상세·수정 화면을 나누는 방식 | 미정 |
| 기록 삭제 전에 확인할 방식 | 미정 |
| 사용할 개발 기술 | 프론트엔드는 React, 백엔드는 FastAPI |
| 데이터베이스 | 실제 서비스는 Supabase PostgreSQL, 로컬 개발·자동 테스트는 SQLite 3 |
| 프론트엔드와 백엔드 운영 장소 | 미정 |
| 웹사이트 주소 | 미정 |

이 항목들은 한 번에 모두 정하지 않고, 구현 전에 필요한 순서대로 하나씩 결정합니다.
